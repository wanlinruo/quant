# Massive Basic 时间范围与夜间市场任务不匹配（#109）

## 现场证据

2026-11-04 20:30 ET（11-05 01:30 UTC），市场展示任务目标 11-04 的日线未就绪：目标覆盖 0%，拆股核对完成，正式快照仍为 11-03，任务按 #106 规则记 MarketDataPending。

同一生产 key 的只读复核：11-04 grouped daily 返回 HTTP 403，消息为 `Attempted to request today's data before end of day`；11-03 同一接口返回 12,607 行。没有读取或输出密钥。11-04 的交易 daily_data、daily_signal、执行与日报均成功，本故障限于首页市场展示。

## 原因

[Massive 官方说明](https://massive.com/knowledge-base/article/on-the-free-basic-plan-when-can-i-pull-the-previous-trading-days-data)：Stocks Basic 的 REST 日线必须等美东午夜跨日，前一交易日才进入可访问范围；当晚收盘以后仍属于当天，返回 403，与每分钟请求限额的 429 不同。这里不是 flat files 的次日上午发布时间。

#106 正确阻止了沿用旧数据却报成功，但没有改变原 20:30 的调度；其晚间 15 分钟重试均早于权限开放时间，不能解决根因。该不足不通过恢复旧的“成功”状态掩盖。

## 修复

- market_data 默认在目标交易日次一自然日 00:10 ET 启动，请求日期、job_runs 与 job_attempts 仍归目标交易日。
- 使用交易日历与 America/New_York 时区：周五数据在周六执行、节日前数据在假日执行；半日市不把午夜任务提前，夏令时不硬编码 UTC。
- 在新执行窗口内最多 4 次尝试，间隔至少 15 分钟，锁内复核；原午夜前失败记录保留，不消耗新窗口次数。401、写入错误及非市场任务仍需人工处理。
- 调度器重启后先处理到点的交易主链；下一交易时段开盘前 2 小时起不启动过期夜间补数，保留 quotes 的独立常规时段追补。
- 系统页时间线按执行自然日展示并标出数据日；告警的手动重跑命令使用数据日，避免在 11-05 午夜错误请求 11-05 数据。
- 保留真实 HTTP 403/429/网络错误摘要，403 不回显未经筛选的上游消息；日期、覆盖率、拆股及原子写入检查保持生效。

冬令时 00:10 ET 对应北京时间同一自然日 13:10，夏令时为 12:10，均为数据交易日的次一自然日。该时间是启动点，补数与市值更新可能延后完成，不承诺即刻就绪。没有购买新套餐、切换交易模式或重跑交易任务。

## 验证范围

回归覆盖跨日归属、节假日/周六、半日市、夏令时、重启、旧窗口失败、新窗口限次、临近开盘避让、系统页日期/告警和源错误脱敏。部署与首个自然执行结果回填 #109；达到计划时间前不宣称目标日已恢复。
